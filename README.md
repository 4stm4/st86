# st86 — стенд «Челябинск-1»

Детерминированная модель платы на КР1810ВМ86 (i8086), работающая целиком в браузере. Автоматический критерий «работает / не работает» для прошивок реального железа.

## Зачем

Стенд решает конкретную задачу: **проверить, укладывается ли прошивка в заданные временные ограничения**. Это не эмулятор ради эмуляции — здесь нет BIOS, нет DOS, нет совместимости с IBM PC. Есть одна ось времени (такты ЦП), детерминированная очередь событий и набор утверждений, которые прошивка либо проходит, либо нет.

**Что даёт разработчику:**

- Прогон прошивки без железа — достаточно браузера
- Измерение worst-case latency в тактах, а не в микросекундах (частота не протекает в утверждения)
- Машиночитаемый вердикт с кодом возврата (0 = успех, 1–4 = разные виды отказа)
- Воспроизводимость: один и тот же образ + сценарий = один и тот же результат, всегда
- Детекция нарушений дисциплины (FIFO-протокол, recovery time на ВИ53/ВН59)
- Fault injection для проверки обработки ошибок

## Быстрый старт

```bash
npm install
npm run dev
```

Откройте `http://localhost:8080` в браузере.

### Первый прогон

1. На главной странице уже выбран образ **boot** и сценарий **boot-basic**
2. Нажмите **«Прогнать сценарий»**
3. Через ~15ms получите вердикт: 6/6 утверждений, код возврата 0

### Попробовать Hello World

1. Выберите образ **hello** в правой панели
2. Замените сценарий в текстовом поле:
```json
{
  "version": 1,
  "name": "hello-world",
  "image": "hello",
  "cycle_limit": 100000,
  "asserts": [
    { "kind": "uart_contains", "text": "Hello, World!" },
    { "kind": "no_violations" }
  ]
}
```
3. Нажмите **«Прогнать сценарий»** — в UART-терминале появится `Hello, World!`, на видеоканвасе — зелёный текст (нажмите «Обновить»)

### Загрузить свой образ

Нажмите «Загрузить свой сырой образ (.bin)» — файл загружается по адресу `CS:IP = 0000:0100`. Напишите сценарий с нужными утверждениями и прогоните.

## Архитектура

```
┌─────────────────────────────────────────────────┐
│  Machine (machine.ts)                           │
│  ┌───────┐  ┌───────┐  ┌──────┐  ┌──────────┐  │
│  │ CPU   │  │ Memory│  │Events│  │ Devices   │  │
│  │ 8086  │  │ 1 MB  │  │Queue │  │           │  │
│  │       │◄─┤       │  │      │  │ PIC (ВН59)│  │
│  │       │  │       │  │      │  │ PIT (ВИ53)│  │
│  │       ├─►│       │  │      │  │ UART      │  │
│  │       │  │       │  │      │  │ Video FIFO│  │
│  │       │  │       │  │      │  │ Disk PIO  │  │
│  └───────┘  └───────┘  └──────┘  └──────────┘  │
│                                                 │
│  step(): events → devices → IRQ → INTA → CPU   │
└─────────────────────────────────────────────────┘
          │
          ▼
┌─────────────────────┐
│ Scenario (JSON v1)  │
│ asserts + limits    │──► Report (JSON)
│ config + faults     │    exit_code 0–4
└─────────────────────┘
```

### Один шаг машины — 5 фаз

1. **Очередь событий** — обработка всех событий с timestamp ≤ clock
2. **Состояния устройств** — обновление PIT, видео-drain, диск
3. **Публикация IRQ** — PIC выставляет линии прерываний
4. **INTA** — если CPU готов, цикл подтверждения прерывания
5. **CPU step** — выполнение одной инструкции с учётом wait states

## Устройства и карта портов

| Порт | Устройство | Описание |
|------|-----------|----------|
| `0x20–0x21` | ВН59А (PIC) | Контроллер прерываний, ICW1–4, EOI, маскирование |
| `0x40–0x43` | ВИ53 (PIT) | 3 канала, ленивый подсчёт, период = счёт × 4 такта |
| `0xD0–0xD4` | Диск (PIO) | LBA + команда + данные, 512 Б/сектор, ~1ms |
| `0xE0–0xE1` | Видео-FIFO | Командный поток для RP2040, протокол «резервируй → пиши» |
| `0xE2–0xE3` | UART | Данные / статус, ввод через rxQueue |
| `0xE4–0xE6` | Видео-статус | FIFO_FREE (16 бит), флаги платы |
| `0xF0–0xF6` | Тестовый порт | Маркеры, finish, semihosting |

## Формат сценария (JSON v1)

```json
{
  "version": 1,
  "name": "имя-сценария",
  "image": "boot",
  "cycle_limit": 5000000,
  "config": {
    "wait_states": {
      "ram": 0, "rom": 0, "timerPic": 1,
      "videoFifo": 0, "recoveryCycles": 8
    }
  },
  "fault": { "kind": "fifo_overflow_flag", "at_cycle": 10000 },
  "asserts": [ ... ]
}
```

### Утверждения

| `kind` | Что проверяет | Пример |
|--------|--------------|--------|
| `checkpoint_order` | Маркеры пройдены в порядке | `{"values": ["boot", "vfs_ready", "done"]}` |
| `metric` | Латентность ≤ порога | `{"name": "max_irq_blocked", "max_cycles": 5000}` |
| `mem` | Байты в памяти | `{"addr": "0x05010", "equals_hex": "DEADBEEF"}` |
| `uart_contains` | Строка в UART | `{"text": "OK"}` |
| `video_stream_hash` | SHA-256 видеопотока | `{"equals": "sha256:..."}` |
| `no_violations` | Нет нарушений дисциплины | `{}` |

### Метрики латентности

- **max_irq_blocked** — максимальное время с CLI до STI (такты)
- **irq_to_wake_max** — от фронта IRQ до маркера `task_wake` (такты)
- **video_idle_cycles** — простой видео-FIFO (потребитель ждёт данных)

### Коды возврата

| Код | Значение |
|-----|----------|
| 0 | Успех — все утверждения пройдены |
| 1 | Провал утверждения |
| 2 | Нарушение дисциплины (FIFO-протокол, recovery time) |
| 3 | Исчерпан `cycle_limit` |
| 4 | Внутренняя ошибка стенда |

## Интерактивные инструменты

### UART-терминал

Двусторонняя консоль: вывод прошивки отображается в реальном времени, ввод отправляется в `uart.rxQueue`. Прошивка читает через `IN 0xE2`, статус через `IN 0xE3` (бит 1 = есть данные).

### Видеовыход RP2040

Canvas 320×240 с 16-цветной палитрой. Рендерит командный поток видео-FIFO:

| Опкод | Команда | Payload |
|-------|---------|---------|
| `0x01` | NOP | — |
| `0x02` | CLEAR | цвет (1 Б) |
| `0x03` | SET_COLOR | fg, bg (2 Б) |
| `0x04` | MOVE_TO | x16, y16 (4 Б) |
| `0x05` | LINE_TO | x16, y16 (4 Б) |
| `0x06` | RECT | x16, y16, w16, h16 (8 Б) |
| `0x07` | TEXT | col, row, char (3 Б) |
| `0x08` | FLUSH | — |

### Страницы UI

## Написание прошивки

Прошивка — сырой бинарный файл, загружаемый в `CS:IP = 0000:0100`. Адресное пространство — 1 МБ (реальный режим 8086). Нет BIOS, нет DOS, нет IVT по умолчанию — всё настраивается прошивкой.

Минимальный шаблон (псевдокод):

```asm
; CS:IP = 0000:0100
CLI
MOV AX, 0
MOV SS, AX
MOV DS, AX
MOV SP, 0xFFFE

; ... ваш код ...

; вывод в UART
MOV AL, 'H'
OUT 0xE2, AL

; завершение (semihosting)
MOV AL, 0       ; код возврата
OUT 0xF4, AL
HLT
```

Встроенный ассемблер (`asm.ts`) можно использовать для генерации образов программно:

```typescript
import { Asm } from "./emulator/asm";

const a = new Asm(0x0100);
a.cli();
a.uart("Hello!");
a.finish(0);
a.hlt();
const binary: Uint8Array = a.build();
```
